# Bring CopilotKit into SET: AG-UI runtime, on-screen Guide agent, voice mode, Slack channel

## Research conclusions (docs.copilotkit.ai, Aug 2026)

- **CopilotKit v2** is Fetch-handler based: `CopilotRuntime` + `createCopilotRuntimeHandler` from `@copilotkit/runtime/v2`. There is no Fastify adapter, but the handler takes a standard `Request` and returns a `Response`, so a thin Fastify bridge route works (hijack reply, forward `req.raw`).
- **Frontend**: `<CopilotKit runtimeUrl agent>` provider + `CopilotChat` / `CopilotPopup` from `@copilotkit/react-core/v2`. Key hooks: `useAgentContext` (screen/page context — replaces v1 `useCopilotReadable`), `useFrontendTool` (client-side tools), `useRenderTool`/`useComponent` (generative UI), `useHumanInTheLoop`.
- **Voice** = speech-to-text: a `TranscriptionService` on the runtime exposes `POST /transcribe`; `/info` then advertises it and the mic button appears in `CopilotChat` automatically. Custom providers = subclass `TranscriptionService.transcribeFile()`. TTS stays browser-side (`speechSynthesis`, already used in A2UI.tsx).
- **A2UI**: runtime option `a2ui: {}` applies A2UI middleware to agents; frontend renders automatically. SET's existing `render_ui` CUSTOM components map naturally onto CopilotKit's **tool-call rendering** primitive (`useRenderTool`).
- **Channels (Slack)**: `@copilotkit/channels@0.6.1` + `@copilotkit/runtime@1.65.0` (pinned pair) in a **long-running Node 22 process** — `createChannel({name, identifyUser:'platform', agent})`, `channel.onMessage(({thread,message}) => thread.runAgent({prompt, context}))`, gateway connection to CopilotKit Intelligence (managed by default, self-hostable via `INTELLIGENCE_API_URL` + `INTELLIGENCE_GATEWAY_WS_URL`).

**Key architectural move**: SET's agent loop (`agents/routes.ts`) already speaks AG-UI-shaped events. Extract it into a shared engine with an `emit(type, payload)` callback, then reuse it from three entry points: the legacy `/api/agent/run` (kept for compat/MCP smoke tests), a new in-process `SetAgent` (AbstractAgent) served by CopilotRuntime for the web UI, and the Slack channel process (which calls the legacy endpoint over HTTP with a minted service JWT — full tool parity, minimal code).

## Phase 1 — Server: extract agent engine + CopilotKit runtime (Fastify bridge)

**Files:**
1. `server/src/agents/engine.ts` (new) — move the loop out of `routes.ts` (lines 94–215): thread persistence, context blocks, skills injection, tool loop, HITL approvals; signature `runAgentLoop({spaceId, userId, threadId, message, context, approvals, emit, registerPending})`.
2. `server/src/agents/routes.ts` — becomes a thin SSE wrapper over the engine (public API unchanged; `pending` map + `/agent/runs/:id/approve` stay).
3. `server/src/copilotkit/agent.ts` (new) — `SetAgent extends AbstractAgent` (from `@ag-ui/core`, dependency of the runtime; exact interface verified from installed types during implementation). Maps engine emits → AG-UI events (`TEXT_MESSAGE_CONTENT`, `TOOL_CALL_START/END`, `RUN_STARTED/FINISHED/ERROR`, CUSTOM a2ui/approval_request — near 1:1 since events were modeled on AG-UI). Reads `spaceId`/`context`/`mode` from the run input's `forwardedProps`/`context`. Guide mode variant swaps in a teaching system prompt (see Phase 3).
4. `server/src/copilotkit/transcribe.ts` (new) — `SetTranscriptionService extends TranscriptionService`: POSTs audio to the space provider's OpenAI-compatible `/audio/transcriptions` (whisper-family model; env override `TRANSCRIBE_MODEL`). Throws an "api key"-style error → runtime 401s gracefully when unsupported.
5. `server/src/copilotkit/runtime.ts` (new) — `new CopilotRuntime({ agents: { set, set_guide }, a2ui: {}, transcriptionService })` + `createCopilotRuntimeHandler({ runtime, basePath: '/api/copilotkit', hooks: { onRequest: auth } })`. Auth verifies Bearer JWT **or** `?token=` via existing `lib/tokens.ts` (same pattern as the WS endpoint).
6. `server/src/copilotkit/route.ts` (new) — Fastify bridge registered in `index.ts` under `/api` prefix: `app.all('/copilotkit/*')`, `reply.hijack()`, build a `Request` (JSON bodies reconstructed from parsed `req.body`; multipart/audio forwarded from `req.raw` stream), pipe the `Response` back through `reply.raw`.
7. `server/src/config.ts` — add `TRANSCRIBE_MODEL`, `CHANNELS_*` (service token secret reuse of `jwtSecret`).
8. `server/package.json` — add `@copilotkit/runtime@1.65.0`, `@ag-ui/core` (types).

## Phase 2 — Web: migrate chat to CopilotKit + voice + dither styling

**Files:**
1. `web/package.json` — add `@copilotkit/react-core` (^1.65).
2. `web/src/lib/copilot.ts` (new) — provider helpers: custom `fetch` attaching the Bearer token to runtime calls (fallback: token query param, bridge accepts both), shared `runtimeUrl`/`agentId` constants, guide/system instruction strings.
3. `web/src/components/AppShell.tsx` — wrap app content in `<CopilotKit runtimeUrl="/api/copilotkit" agent="set" useSingleEndpoint={false}>`; register `useAgentContext` for current space/view/route; render `<GuideFab/>`; keep the copilot toggle button opening the rebuilt panel.
4. `web/src/components/CopilotPanel.tsx` — rebuild on `<CopilotChat>`: keep the outer aside shell, swipe-to-close, and Mascot header (via `header` slot); `useRenderTool('render_ui')` + SET A2UI components (card/kv/table/quiz/flashcards/viewer3d/form/list) as renderers; approval cards rendered from the CUSTOM approval_request event; **mic button appears automatically** once transcription is live; add a "speak replies" toggle (speechSynthesis, reusing A2UI.tsx:228-250 pattern) for full voice mode.
5. `web/src/lib/voiceFallback.ts` (new) — Web Speech API (`webkitSpeechRecognition`) dictation used when `/info` reports transcription unavailable, so voice works with pure-local BYOK setups.
6. **dither-kit everywhere** — new surfaces styled with the local kit (`dither-kit/button.tsx`, `avatar.tsx`, dithered textures): guide FAB + popup chrome, voice/mic states (dithered `sparkline` waveform while recording/speaking), quiz/flashcard A2UI results gain dithered bar/radar charts, channel status cards.
7. Views register `useAgentContext`: `PageView` (title + markdown outline + selection), `DatabaseView` (schema/columns), `NotebookView` (id/title), `DashboardView`.

## Phase 3 — On-screen Guide agent ("tooltip that teaches SET")

**Files:**
1. `web/src/components/GuideFab.tsx` (new) — floating dither-styled launcher (Mascot mini) → `<CopilotPopup agentId="set_guide">` with custom `toggleButton` slot. Available on every view; presses open a context-aware helper.
2. `web/src/components/GuideTools.tsx` (new) — `useFrontendTool` registrations:
   - `insert_into_editor(markdown)` — inserts at cursor via editor bridge;
   - `highlight_element(selector)` / `start_tour()` — reuses driver.js + existing `data-tour` attributes for teach-mode spotlighting;
   - `navigate(path)` — router push;
   - `explain_screen()` — summarizes the `useAgentContext` payload.
3. `web/src/lib/editorBridge.ts` (new) — tiny pub/sub between PageView's TipTap editor and the guide tools (insert content, read selection).
4. Server: `set_guide` agent (same engine, guide system prompt: explain current screen, help fill notes, teach SET features, prefer frontend tools).

## Phase 4 — Slack channel (two-way: add to SET / pull from SET)

**Files:**
1. `channels/` (new package, Node 22) — `package.json` (pinned `@copilotkit/channels@0.6.1` + `@copilotkit/runtime@1.65.0`), `tsconfig.json`, `Dockerfile` (node:22-alpine, tsx runtime).
2. `channels/src/channel.ts` — listener per docs: `createChannel({ name: CHANNEL_CODE, identifyUser: 'platform', agent })`; `onMessage` resolves the Slack context → SET space/user, then `thread.runAgent()`.
3. `channels/src/setAgent.ts` — `AbstractAgent` whose `run()` calls SET's legacy `POST /api/agent/run` with a service JWT (minted from shared `JWT_SECRET` for a dedicated `slack-bot` service identity) and pipes SSE → AG-UI events. Space resolution: `channel_links` mapping (Slack team/channel → space). Unlinked → agent replies with a connect link.
4. `server/sql/011_channels.sql` — `channel_links` table (platform, platform_id, space_id, linked_by, created_at).
5. `server/src/channels/routes.ts` (new) — link/unlink + status endpoints (owner-only).
6. `web/src/views/SettingsView.tsx` — new **Channels** tab: channel status (online/offline), link a space to Slack, unlink.
7. `docker-compose.yml` — `channels` service under a `channels` profile (env: `INTELLIGENCE_API_KEY`, `CHANNEL_CODE`, optional `INTELLIGENCE_API_URL`/`INTELLIGENCE_GATEWAY_WS_URL` for self-hosting, `JWT_SECRET`, `SET_API_URL`).
8. `.env.example` — document all new vars (Intelligence keys, `TRANSCRIBE_MODEL`, channels).

## Defaults taken (questions went unanswered)

- Slack via **managed Intelligence**, env-overridable for self-hosting; agent/tools/data stay on SET's server either way.
- Voice: **server STT with browser Web Speech fallback**.
- **Hard cut** of CopilotPanel UI to CopilotChat; legacy `/agent/run` endpoint kept (channels + smoke tests use it).
